# Provider 配置独立为一级分组「认证源」

管理端的 Provider 配置不再放在设置组「登录方式」Tab 里,而与「应用」「API 资源」并列成一级分组「认证源」,下分列表 → 选类型页 → 编辑页(编辑页即详情页)。Provider 是对象集合:多个实例,各有不可改字段、回调 URL、已绑定人数,形状和设置的单页表单不同;「登录方式」Tab 里剩下的密码、必须绑定手机号、用户协议、两步验证是实例开关,留在设置里。这推翻了最近才做的「登录并入设置」(issue #68)。

## Considered Options

- **留在设置组「登录方式」Tab**(`consoles.md` 原先的落点):设置组是单页几个 Tab 的表单形状,再塞进列表、类型目录和详情页就不成立了。
- **另设「登录」分组,把登录方式、认证源、通道都收进去**:查过的产品里只有 Logto、TopIAM 是"外部 IdP + 通道合一、登录方式另立";这么做要连带搬家通道与登录方式,超出本次范围。而"通道放进设置"反而是主流。
- **列表页 + 弹窗编辑**:视觉规范要求详情用独立页、可以链接,不用抽屉或弹窗。

## Consequences

- 管理端(导航、页面、审计)的界面用语 `Provider` 从「外部登录」改成「认证源」;登录页和账号中心面向最终用户,仍叫「外部登录」,「认证源」是管理员的配置术语。`External Identity` 仍叫「外部账号」;`GLOSSARY.md` 的领域术语 Provider / Provider 类型不变(界面叫法归 `consoles.md` 的对照表)。
- 旧的 `/console/settings?tab=login` 不做重定向。
- 权限不变,仍用 `config:read` / `config:write`,与设置同一粒度;国内商业产品没有一家为 IdP 配置单设权限点。
